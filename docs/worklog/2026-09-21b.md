# 2026-09-21 (later) — what a screenshot of the console showed

Four screenshots from the hosted pilot, each of a real screen, each with something wrong that
no unit test could have caught because every unit was right.

## A Gurgaon driveway 760 metres from Bengaluru

The renter searched Bengaluru and the first result said "gurgaon". The listing's coordinates were
in Bengaluru — the host had typed the city into a free-text box and never moved the marker off
the map's default centre. The search is by distance, so it did exactly as asked.

Two fixes, one at each end. The city is now a catalogue (`Cities.cs`: name, centre, radius, time
zone) and a dropdown, and `ListingService.CreateDraftAsync` refuses a pin that is not within the
chosen city's radius, with a message that says which of the two to move. The catalogue is code
rather than a table on purpose: opening a city is a decision somebody takes, with a price band to
add and a launch to plan, and a row a form can insert would make "we operate in Testville" a
typo away. Anyone who wants a city that is not there asks for it — `city_requests`, one row per
person per city, listed on the pricing-bands page most-wanted first, since adding a city *is*
adding a band.

The old row is still in the database. The API refuses new ones like it; the reset below removes
the old one.

## A black pill with no words on it

The selected scope chip on the bookings page went black-on-black under the pointer. The generic
`button:hover` rule sets the text colour to ink and `.chip.selected:hover` only re-set the
background. One line of CSS. An end-to-end test now hovers it and reads the computed colour back.

## "24 hours" seven times

The listing page rendered availability windows as amenity tiles — one per weekday, all saying
"24 hours", none saying which day. The API writes enums as names, so `dayOfWeek` arrived as
"Monday" and `DAY_NAMES["Monday"]` was undefined, which is why the day was missing from every
tile. It is now a "When you can park" section: one line when it is the common case ("Open 24
hours, every day"), a Monday-first week with "Closed" where it applies otherwise.

## A ledger trail nobody could read

Eight rows of debits and credits across four accounts to say "you were charged ninety rupees".
Correct, complete, and useless to the person it was shown to.

Three things changed:

- **A strip at the top of the booking page** answers the three questions anyone opens it with:
  what state is it in, when is it, what did it cost — and one sentence saying how it ended.
  `describeMoney()` derives the sentence and the breakdown from the same figures, once, so the
  page and the receipt cannot disagree.
- **A receipt** at `/bookings/:id/receipt`: overview, breakdown, transactions, outcome. Print is
  the PDF. Every browser saves a printed page as one, and a receipt rendered in the browser from
  the same figures cannot drift from the page the way a server-rendered PDF would.
- **A reference on every transaction.** `TXN-` plus ten characters from an alphabet with no
  0/O/1/I, because it is read aloud and typed into a support form. Unique, minted once, never the
  key anything joins on. And `RevertsTransactionId`: a release points at the hold it returns, a
  payout refund at the payout, a dispute adjustment at the settlement it corrects — so a wallet
  line says "reverses TXN-…" rather than leaving the renter to pair a plus with a minus by
  amount. Existing rows were backfilled from their ids in the migration, before the unique index
  went on.

The platform's own share was nowhere. It is now on the admin's profile, read straight off the
ledger's `PlatformRevenue` account — commission credited less what disputes charged back — so
there is no second copy of the number to reconcile.

## The decide form that looked like nothing happened

"Decide" on a dispute row rendered a form somewhere below the table. It is a dialog now, with
Escape and a backdrop click to close, and a Playwright test that opens it.

## Photos before leaving

The listing form saved and navigated away; the upload lived on the listings page, where a host
who had just finished a form would not think to look. The form now becomes a photo step after
saving — up to six, the first is the cover — and only then offers Done.

## The reset button

A free database tier and a month of test bookings. `POST /api/admin/platform/reset` truncates
every table except users, refresh tokens and the price bands (the list is read off the EF model,
so a table added next month is wiped next month too), and resets KYC status and trust scores on
the accounts that survive. Three gates: the admin role, `Maintenance:AllowDataReset` (off by
default; Production refuses to start with it on), and the phrase `RESET ALL DATA` typed by hand.

## The end-to-end suite

`clients/admin/e2e`, Playwright, against the real stack: the Angular dev server and the API in
Development, where the sandbox gateway needs no account and the OTP code is on the page. It
drives the Chrome already on the machine (`channel: 'chrome'`) because this laptop cannot reach
Playwright's CDN. Fourteen tests, each run at desktop and Pixel 7 sizes: sign-in, listing with
the city dropdown and the photo step, the always-open listing page, a booking through reserve →
cancel → receipt, a completed session's breakdown, the wallet's references, the search tagged
with the right city, the hover bug, analytics gated to the admin, the profile's revenue and reset
gate, and the dispute dialog.

Test setup goes through the API — one OTP per account per run, cached — and Development lifts
the per-IP OTP ceilings (`RateLimits` in `appsettings.Development.json`, now configuration rather
than constants) so fourteen sign-ins are not throttled at the fourth. The production values are
the `RateLimitOptions` defaults.

```bash
npm run e2e          # clients/admin, with the API already running
npm run e2e:report   # the HTML report
```
