## Decisions

Four ADRs written up, because each of these will otherwise get re-argued later:

- [0001](../adr/0001-modular-monolith.md) — modular monolith over microservices for Phase 0. The
  ledger wants hold/debit/settle in one database transaction; splitting Booking from Wallet on day
  one would mean sagas for a problem `BEGIN`/`COMMIT` solves free.
- [0002](../adr/0002-double-entry-ledger.md) — real double-entry with system accounts, not a
  balance column plus a log.
- [0003](../adr/0003-geo-search-without-nts.md) — lat/lng in the domain, PostGIS generated column
  + raw SQL for search. Keeps the test suite on SQLite.
- [0004](../adr/0004-credits-are-not-a-wallet.md) — credits as an accounting layer over an
  aggregator's escrow account, per PRD §16.

## Things that bit

**SQLite can't compare `DateTimeOffset`.** The booking-overlap check does a range comparison on
it, which EF simply cannot translate for SQLite — ten tests failed with the same untranslatable
LINQ error. Fixed with a provider-conditional `DateTimeOffsetToBinaryConverter` in
`ConfigureConventions`. Safe because everything written is UTC; Postgres keeps native `timestamptz`.

Worth knowing: the first error message pointed at `blocking.Contains(b.Status)`, which was a red
herring. Rewriting that to explicit `||` comparisons changed the message but not the failure — the
`DateTimeOffset` comparison was the real cause both times.

**dotnet-ef global tool was in a broken state** (a partial 9.0.8 install that couldn't uninstall
itself). Sidestepped with a local tool manifest at `.config/dotnet-tools.json` pinned to 8.0.10,
which is better practice anyway — the version is now pinned for anyone who clones.
