# 2026-08-04 — the recharge path, end to end

## Where this started

Two things, in order.

First, a `docs/system-overview.md` was written: problem, solution, what exists, the database
structure, and an honest ranking of where load will hurt. Writing it against the code rather than
against the older docs turned up a few drifts — `architecture.md` still claims authentication is
"deliberately missing" (it landed in `b48a596`), and the test count in the README was stale.

Then: build out payments properly, on something free.

## The thing that had to be said out loud

The ask was an "open source free payment gateway". There isn't one, and there can't be — settling
funds requires a licensed PSP. Everything marketed that way is a client SDK for a commercial
provider, or a mock.

So the choice was between Razorpay test mode (free, but needs a signup and an ngrok tunnel for
webhooks, and cannot run in CI) and a self-hosted mock. We took both: a sandbox gateway as the
Development default, Razorpay still wired for the moment credentials exist. Reasoning in
[adr/0006](../adr/0006-sandbox-payment-gateway.md).

## What was built

`SandboxPaymentGateway` — a third `IPaymentGateway` that runs in-process, serves its own checkout
page at `/sandbox/checkout/{providerOrderId}`, signs HMAC-SHA256 callbacks over the raw body, and
emits Razorpay's event envelope including the captured-versus-authorized distinction.

The important decision inside it: **reproduce the protocol, not the outcome.** A mock that simply
credited a wallet would prove nothing. This one can only credit by producing a signature our own
verification accepts, so `SandboxPaymentTests` covering tampering, replay and cross-instance
signatures are statements about the *real* integration.

The checkout page posts the signed body from the browser rather than the server looping back to
itself. That exercises the true HTTP path — including `Request.EnableBuffering()` and the raw-body
read, which is exactly where a signature check quietly breaks — with no self-call and no base-URL
configuration.

Also: `GET /api/payments/orders/{id}`, because the browser's return from checkout proves only that
the user came back. The Angular wallet page polls it.

## Two things that had to change for providers to be genuinely swappable

1. The webhook endpoint read `X-Razorpay-Signature` from a hard-coded string. `IPaymentGateway`
   now carries `SignatureHeader` and the controller asks. Swapping providers would otherwise have
   silently broken verification.
2. `PaymentOptions.IsConfigured` meant "not None". It now means "a real gateway with real
   credentials", explicitly excluding the sandbox — that flag decides whether real money can move,
   and the sandbox must never be able to answer yes to it.

## Traps hit

**The sandbox registration has to be a singleton.** With no `WebhookSecret` configured it generates
a random signing key in its constructor; a scoped registration would sign the checkout page with
one key and verify the callback with another, and every payment would 401. Noted in the DI comment
so it does not get "tidied" later.

**`catchError` was in the wrong place in the Angular poll.** Sitting after `switchMap` it would
complete the whole stream on the first failed request, ending the wait instead of costing it one
attempt. It belongs inside the inner observable.

## Verified

125 tests green. Then driven for real against Postgres and the running API:

| Case | Result |
|---|---|
| Tampered body, valid signature | 401, nothing credited |
| No signature | 401, nothing credited |
| Genuine signed capture | 200 `Credited.`, wallet 0 → 750 |
| Same callback replayed twice more | 200 `Already processed.`, still 750, one `Recharge` transaction |
| Simulated decline | 200 `Recorded failure.`, order `Failed`, balance untouched |
| Ledger replay after all of it | `matches: true` |

Angular build clean; the wallet page's recharge flow was not clicked through in a browser — there
is no browser driver in this environment, so that is worth doing by hand.

## Left dangling

- Rate limiting still absent, and the webhook endpoint is anonymous. Its signature check holds, but
  an attacker can force an unbounded HMAC per request. Same fix as the OTP endpoint.
- `PaymentOrder` has a `Cancelled` status that nothing ever sets. Abandoned orders sit in `Created`
  forever. Wants an expiry sweep.
- Razorpay's path is still unexercised against the live API — the sandbox proves the shape, not
  their particular JSON.
