# Hosting ParkNest on Render + Neon, for ₹0

**Written:** 2026-09-12. Free tiers change; check the provider's pricing page if anything below looks off.

> **Render asks for a card at signup, even for the free instance** (seen 2026-09-12, for both
> Blueprints and a manually created web service). Nothing is charged on the free plan, but if a
> card is not acceptable use [hosting-back4app-neon.md](hosting-back4app-neon.md) instead.

One Render web service runs the API with the admin site built into it, and a Neon Postgres
database holds the data. Nothing here costs money or needs KYC. The mobile app points at the
same URL.

| Piece | Where | Free-tier shape |
|---|---|---|
| API + admin site | Render web service, Docker | 512 MB, sleeps after 15 min idle, wakes on the next request (about 30 s) |
| Postgres + PostGIS | Neon | 0.5 GB, one project, scales to zero when idle |
| TLS, domain | Render | `https://<name>.onrender.com`, certificate included |
| Sign-in codes | Gmail SMTP | App Password, same as local development |
| Payments | Cashfree sandbox | test keys, no money moves |

The API runs as **Staging**: real hosting, but Cashfree test keys and `Mode=Test` are still
allowed. Production refuses both, so switch `ASPNETCORE_ENVIRONMENT` to `Production` only when
live Cashfree keys exist. Either way SMTP is required: outside Development the development
"Log" sender, which returns the code in the response, is never registered, so a real sign-in
channel must exist and phone sign-in is off until an SMS provider is configured.

## 1. Database: Neon

1. Sign up at <https://neon.tech> (GitHub or email). Create a project. Pick the Singapore region if
   offered; it is the closest to India and to Render's Singapore region.
2. In the SQL editor run once:

   ```sql
   CREATE EXTENSION IF NOT EXISTS postgis;
   CREATE EXTENSION IF NOT EXISTS btree_gist;
   ```

   The migrations also do this, but a database owner has to be the one creating extensions on
   Neon, and doing it here first makes the first deploy boring.
3. Dashboard → Connection details → **Direct connection** (not the pooled one; migrations need a
   direct connection). Build the .NET connection string from it:

   ```
   Host=ep-xxxx.ap-southeast-1.aws.neon.tech;Database=neondb;Username=neondb_owner;Password=…;SSL Mode=Require;Trust Server Certificate=true
   ```

   Neon databases are UTF-8, which the API checks at startup.

## 2. Service: Render

1. Sign up at <https://render.com> with GitHub and allow it to see the `ParkNest` repository.
2. **New → Blueprint**, pick the repository and the branch. Render reads [`render.yaml`](../render.yaml)
   and creates one web service named `parknest` built from the [`Dockerfile`](../Dockerfile).
3. It stops and asks for every variable marked `sync: false`. Fill them in:

   | Variable | Value |
   |---|---|
   | `ConnectionStrings__ParkNest` | the Neon string from step 1 |
   | `Auth__AdminEmails__0` | your email address; that account becomes the platform admin |
   | `Email__Username`, `Email__FromAddress` | your Gmail address |
   | `Email__Password` | the 16-character Gmail App Password (`scripts/connect-gmail.ps1` stored the same one locally) |
   | `Payments__PublicBaseUrl` | `https://parknest.onrender.com`, or whatever name Render gave the service, no trailing slash |
   | `Payments__ReturnUrls__admin` | that URL plus `/wallet` |
   | `Payments__Cashfree__ClientId`, `Payments__Cashfree__ClientSecret` | the Cashfree **Test** App ID and secret |

   `Auth__SigningKey`, `Auth__OtpPepper` and `Kyc__Pepper` are generated by Render. Startup
   refuses the `dev-only` placeholders from `appsettings.json` outside Development, which is
   why they have to exist.
4. Deploy. The first build takes about 10 minutes (Angular, then .NET). On start the API applies
   its own migrations, because `Database__MigrateOnStartup=true`; the log shows which ones.
5. Open `https://<name>.onrender.com/health` → `{"status":"ok"}`. Then open the root: the admin
   sign-in page, served by the API itself.

## 3. Cashfree webhook (optional but now possible)

Render's URL is public https, which is what Cashfree requires for webhooks. In the Cashfree
dashboard → Developers → Webhooks → Payment Gateway, add
`https://<name>.onrender.com/api/payments/webhook`, events *Payment success* and *Payment
failed*, version `2026-01-01`. No secret to enter: Cashfree signs with the client secret.

The API credits an order even without the webhook, by asking Cashfree when the browser comes
back, so this only makes confirmation faster and covers the case where the user closes the tab.

## 4. Mobile app

Build the app with the hosted URL; `AppConfig.apiBaseUrl` reads it from a compile-time define:

```bash
flutter build apk --dart-define=PARKNEST_API_BASE_URL=https://<name>.onrender.com
```

The checkout page and the "return to the app" page are served by the same host.

## What the free tier costs you

- **Cold starts.** After 15 idle minutes the first request waits about 30 s. A free
  [cron-job.org](https://cron-job.org) ping to `/health` every 10 minutes keeps it warm, within
  Render's 750 free hours a month for one service.
- **Photos do not survive a deploy.** `Storage:Provider=Local` writes to the container's disk.
  Object storage (Cloudflare R2 has a free 10 GB tier) is the fix when listing photos matter.
- **One instance.** `MigrateOnStartup` is safe because the free plan runs exactly one; turn it
  off and run `dotnet ef database update` from CI before scaling out.
- **Grafana/Prometheus** from `ops/` are not deployed; `/metrics` is exposed on the service and
  can be scraped from anywhere until it is firewalled, so treat the numbers as public for now.

## Going live later

Production needs: Cashfree KYC approved and live keys (`Payments__Mode=Live`, `cfsk_ma_prod_…`),
`ASPNETCORE_ENVIRONMENT=Production`, a current account in the business name for settlements,
and the policy pages Cashfree asks for. See [payment-gateway-setup-fully-free-rnd.md §7](payment-gateway-setup-fully-free-rnd.md#7-legal-and-compliance-notes-read-before-going-live)
before real users.
